# Embedded Chinese speech fallback

CompletionSpeech prefers an installed system TextToSpeech engine with Chinese
support. If initialization or speaking fails, it invokes the internal
`EmbeddedChineseTts(context).use { it.speak(text, current) }` on its worker thread.
The caller owns audio focus and the `current` cancellation predicate. There is
no network speech request and no downloaded runtime engine at playback time.

## Engine and assets

Inference uses `com.microsoft.onnxruntime:onnxruntime-android:1.22.0` (MIT) and the
unchanged Kokoro-82M-v1.1-zh int8 model (Apache 2.0). The Chinese zf_001 voice is
the original speaker index 3. One 522240-byte style table and a 1709577-byte
Chinese lexicon accompany the 114299010-byte model. The lexicon contains 68003
entries generated by upstream from misaki (Apache 2.0) and pypinyin (MIT).
Complete source links and notices are in `docs/licenses/embedded-chinese-tts.txt`.

Only model.int8.onnx, voice.bin, lexicon.bin, APACHE-2.0.txt, NOTICE.txt and
manifest.json are included. The source archive also contains espeak-ng assets;
none of those files, the sherpa-onnx runtime, other-language lexicons, Jieba data,
or normalization FSTs are bundled or linked. The model's `has_espeak` metadata
describes the upstream frontend, not an executable dependency of this adapter.

Official source archive:
https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/kokoro-int8-multi-lang-v1_1.tar.bz2

SHA-256:
`a1e94694776049035c4f2c6529f003aaece993c76aae9a78995831c3c4dcafc6`

This digest was matched to the release asset's official GitHub API digest before
extraction. Preparation only reads an exact list of regular archive members and
verifies their expected sizes. It never extracts the archive tree wholesale.
The generated manifest records each selected asset's SHA-256 and transformations.

## Preparing an offline build

```sh
python scripts/prepare-embedded-tts.py --download
```

The download flag is only needed on a machine without the pinned archive in
`.tooling/tts`. Normal preparation makes no network request:

```sh
python scripts/prepare-embedded-tts.py
```

The default generated asset root is `android/sdk/build/generated/ttsAssets`;
`--output` can change that root. Gradle adds this directory to the SDK's main
assets. Every host **application** module must keep the `onnx` extension uncompressed;
the library's setting does not propagate into the final APK. Add this to each
host's `android` block:

```kotlin
androidResources { noCompress += "onnx" }
```

Dependency caches and the
source archive must already exist for a fully offline build. No model binaries
belong in Git. A clean build regenerates assets from the verified archive.

R8 must preserve ONNX Runtime JNI classes:

```proguard
-keep class ai.onnxruntime.** { *; }
```

## Runtime behavior

Resources load only when the fallback is actually needed. Android's asset file
descriptor is memory mapped directly into ONNX Runtime; user text, generated PCM
and task results are never written to a model cache or audio file. The model is
opened with two intra-operation threads, one inter-operation thread, and memory
pattern optimization disabled. Closing the fallback releases the session and
lexicon. The global ORT environment is shared as intended by that library.

Chinese phrases use longest dictionary matching and the published pronunciations.
Punctuation splits sentences; long sentences are bounded to 96 phonemes per
inference, well below the model's 510-row style limit. Numeric values use Android's
public ICU MessageFormat `spellout` format. Long numbers, leading zeros, fractional
digits and unavailable ICU rule data fall back to digit-by-digit reading. Latin
letters are spoken by letter name. This fallback is not a general English or
multilingual pronunciation engine; unsupported rare characters may be omitted,
and dictionary pronunciation cannot resolve every contextual heteronym.

Inference and playback overlap with one bounded queued PCM chunk. AudioTrack
plays 24 kHz mono PCM16, with no file output. A 40 ms cancellation watcher can
terminate the active ORT run, and playback checks the same predicate between
nonblocking writes. Every inference has a 30-second deadline; audio device stalls
are bounded. Cancellation suppresses remaining chunks and releases audio output.
The caller stops speech for calls, lock-screen transitions, disabled completion
speech, or a superseding result. CPU speed, memory and audio latency still vary by
device; an absent or failed fallback leaves the visible result available.

## Verification

Pure JVM tests cover phrase preference, boundary tokens, long sentence splitting,
punctuation and exact digit spelling. To repeat the actual model smoke test:

```sh
python -m pip install onnxruntime==1.22.0
python scripts/verify-embedded-tts.py
```

This development script writes only two fixed public fixture sentences to WAV
under `.artifacts/tts`, verifies asset checksums and measures actual CPU inference.
It does not record user text. Initial desktop results were 2.8 seconds of audio
in 2.188 seconds and 3.975 seconds in 3.531 seconds, with finite samples and RMS
around 0.059. These are local CPU measurements, not phone performance claims or
a pronunciation evaluation. Android playback, cancellation, number formatting
and memory evidence require separate device validation; desktop fixtures do not
establish that acceptance.
