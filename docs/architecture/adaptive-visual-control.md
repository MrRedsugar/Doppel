历史范围：当前 App 直连入口是 `DirectRuntime → SplitTaskEngine`。本文保留 2026-09-09 旧 `DirectTaskEngine` 的设计和当时验证边界，不是当前运行链的操作或集成指南。旧引擎的 15 个实现文件（共 17 个顶层类，包括 `VisualAgentLoop`、`ActionProgress`）已迁至 `android/sdk/src/test/java/dev/doppel/sdk/legacy/`，包名不变，仅用于 JVM 历史测试。

原记录日期为 2026-09-09，执行范围见 worklog123。下文描述当时的自研核心及验证边界，不代表第三方 App 业务任务已全面通过。

## 方案比较与选择

仅更换更大模型能提升某些定位，但不能修复无效动作无限重复、缺少覆盖证据和协议错配。整体换用Artemis Pro会引入计划/Checker等额外调用及Python依赖，此前接入结果也未证明更优。本轮选择在自研核心中加入明确的目标几何、短期视觉历史、动作效果状态与恢复通道，专用GUI模型保留独立接口和离线选型证据，不把模型、UI解析器和完整Agent混为一谈。

## 数据与组件

- 旧 `DirectRuntime → DirectTaskEngine` 接线：当时 App 直连运行时显式开启 `visualControl=true`、`preferVisualObservation=true`。设备声明可用的截图及视觉手势能力，且当前不在助手自身界面时，即使有语义控件也优先进入视觉执行；缺少当前图时先请求新截图。Android 8–10须有有效屏幕共享会话。当时内部 `DirectTaskEngine` 的构造参数默认是 `false`，保留原有语义路径；这些旧构造参数不适用于当前 Split 入口。
- `ScreenCapturePrivacy`：Android宿主逐次观察声明登录隐私截图不可用，绑定当前 `screen_id`、包名、采集时间及固定来源/原因，不含手机号、验证码或授权。匹配期间只走既有脱敏语义路径，清空当前/历史图和待处理视觉问题，不向模型提供截图或视觉定位工具；新观察不再携带匹配状态时恢复视觉策略。组合观察缺图仅在 `data.screenshot_omitted_reason=login_sensitive` 与该状态同时匹配时允许，普通缺图、直接截图拒绝及视觉动作后的必要核验均不被豁免。本机资料设置、验证和付款门禁保留，不重放已执行输入；该实现不代表真实账号登录已验收通过。
- `ModelScreenSummary`（共享 API 仍保留，此处记录旧引擎的使用方式）：所有可交互目标附带设备坐标bounds和区域，保留selected/checked及小范围父级关系；视觉消息把设备坐标转换为当前截图整数像素，不能把设备坐标直接送到截图坐标工具。
- `ActionProgress`：宿主记录动作类型、实际几何、前后语义或像素状态和观察结果。字段不含输入内容、批准或执行令牌。只有可比较证据相同才认定未观察到变化，未知不能假称没变化；页面变化不能当任务成功。
- `VisualActionHistory` / `VisualAgentLoop`：仅在宿主收到已接受、非 `no_op` 的实际动作结果后保存其源图及动作，最多两张；不是模型提议、拒绝动作或独立的执行后截图。发送时按先旧后新的顺序排列历史图，当前图放在最后。历史图还受图像字节预算约束，可能少于两张；旧坐标不能直接执行。图像只作短期运行上下文，结束/恢复时清除，磁盘截图仍遵守已有保留边界。
- `ModelActionHistory`：合并宿主动作记录，最多向模型展示最近六条简短动作与效果说明；输入内容省略，旧坐标和历史解读不是当前执行依据。该压缩仅作用于模型消息，本机诊断记录的完整字段继续保留，仍遵守已有脱敏、条数和磁盘上限。
- `DirectTaskEngine`：仅对可比较的同页面、同目标点击或长按，在最近两次动作均可靠判为 `unchanged`、当前画面仍相同时阻止第三次重复提议，返回结构化反馈。其他操作仍由模型根据当前证据选择。只有明确未执行的可恢复节点失败可以继续规划，不自动重放不确定的写操作。
- 模型动作schema：点击与长按不含滑动终点，拒绝真实冲突参数并提供字段级反馈。缺少工具调用及部分视觉格式错误有各自最多两次的有限纠正预算，有效响应重置相应连续错误计数。纠正会重新观察并发起模型调用，实际消耗调用次数、时间和提供商额度。
- 输入：沿用当前可编辑节点设置文本。明确未执行的节点失败可返回模型，重新观察编辑状态，再选择当前画面可见的确认、返回等操作。此次 WPS 是通过界面完成提交；没有新增通用 IME 完成/下一步工具，也未增加 ADB 键盘注入。语音、输入法切换和未知焦点的回车不属于此次已验证能力，不得以通用回车绕过发送、支付或认证边界。

## 完成与列表

完成仍必须携带当前证据；该检查验证来源和新鲜度，不独立判定业务事实。`ActionProgress`只覆盖有可靠 `unchanged` 证据的重复目标，不是通用循环检测器，也不是完整列表扫描或数量统计的裁判。动画或不透明画面的像素不同可能仍是 `unknown`，输入效果也保持未知；它不会据此宣称成功或阻止所有形式的重复操作。不同App的实际结果、列表首尾、跨页重叠及全量覆盖仍须另行验证，不能以“当前可见”代替“完整扫描”。
