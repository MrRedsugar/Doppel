# 分层规划、快速执行与混合感知

历史范围：当前 App 直连入口是 `DirectRuntime → SplitTaskEngine`。本文保留 2026-09-09 的旧分层计划设计、实验条件和验收目标，不是当前 App 的启用指南，也不表示下列方案均已在当前运行链实现。旧引擎的 15 个实现文件（共 17 个顶层类，包括 `DirectTaskEngine`、`GuardedActionPlan`）已迁至 `android/sdk/src/test/java/dev/doppel/sdk/legacy/`，包名不变，仅用于 JVM 历史测试；不能再按本文从生产 SDK 构造旧引擎或启用这些计划工具。

共享的 `ModelScreenSummary` 和生产观察仍使用的 `ObservationCoverage` 采集器继续保留；它们不等于下述旧计划执行机制。旧设备实验 `LearningLiveTest`、`PerceptionLiveTest` 已移至 `labs/legacy-direct-engine/androidTest/`，不再默认编译。以下历史验收目标不代表当前版本已实现或通过，具体结果见对应版本验证记录。

原记录日期为 2026-09-09，承接 alpha19，记录当时已授权的实施范围。重大变更及快照见 worklog125-planned-fast-control，先前 125-perception 文档是子范围记录。

## 问题与选择

失败并非一个坐标或一种中文输入法造成：旧路径把高层规划与单步操作耦合；依赖文字视觉问答；对节点树/业务进度混淆；没有连续动作执行器、画布局部跟踪、专用定位模型和可用shell权限后端。

比较三种方案：每步调用更大模型仍有往返延迟；录制一串坐标重放无法处理变化；采用有条件的短程计划，每步本地读取当前状态，出现偏差再交高层。选择第三种，保留原自研宿主的授权、取消、回执和会话。

## 组件与接口

1. 高层规划：MiMo结合目标、当前图/控件和已验证历史，输出阶段目标、短程steps及可检查结果。阶段之间需要当前证据，不从工具接受推断业务完成。常规语义计划使用execute_plan，图像计划使用execute_visual_plan；语义段最多12步、视觉段最多8步，TTL有界，重启或暂停失效，最终Done只触发核验。
2. GuardedActionPlan：保存短程步骤，用新观察中的text/description/resource/role/selected/focused选择唯一节点，禁止存旧node ID。每步when/expect不成立或目标歧义时停止该段；核验需新回执/观察。模型调用、计划步骤、捕获、定位、执行各自计时。
3. VisualAnchorPlan/Tracker：由当前源图构建有辨识度的局部锚点，在后续帧有限区域重新匹配。低纹理、重复、遮挡、旋转/尺寸变化或时效不符则停止并返回原因；锚点不提供授权，输出当前像素候选继续走VisualGesture契约。高帧率采集和局部跟踪不等于理解所有战斗语义。
4. 混合感知：正常可访问页面用新控件树连续执行；首轮规划、歧义、画布/图标及核验需要截图。删除生产计划模式的截图问答中转。专用GUI服务采用当前image+单一目标返回point/无法定位，严格绑定capture/hash/尺寸，不执行动作。两款官方固定模型在相同真实截图评估后选择，不以外部榜单替代实测。
5. ShellBridge：已授权ADB启动手机内shell UID2000 helper，应用通过经peer UID验证的本地socket调用受限typed能力。无任意模型shell，不在结果不明后换后端重复写。无障碍原生节点点击仍优先，shell补充视觉手势、系统按键、截图；输入由当前编辑器绑定的IME接口控制。Android9验证shell后端，Android11+无线TLS配对作为另一项真实设备验证，不能假造模拟器支持。
6. 恢复与范围：动作失败可重新定位、获取新截图、选择实际可用输入提交方式；追踪重复路径及失败阶段，不能把hash变化视作有效进度。列表统计需记录扫描方向、相邻页重叠、首尾/当前视口范围，不能在没有完整覆盖证据时宣称全部。意外弹窗/通知用现有安全恢复，来电等边界停止局部段并保留原因。
7. 游戏：在支持暂停的场景先暂停，识别当前编队/费用/地图/出入口/部署格/朝向，制定一段可执行计划；恢复后用本地观察及锚点执行部署和方向动作；出现预期差异重新暂停/规划。技能和地图资料只是参考，不能代替实际编队及画面。TR-9实际成功或失败都保存证据，不以离线模板测试替代通关。
8. 调试：既有device-lab补可视化与连续帧预览/采集，操作员动作有独立账本。评测目标通过真实Doppel入口运行；手工准备与收尾不计作Agent成功。

## 当时的验收目标与测量

- 常规导航/计算：连续不少于3个实际控件动作由本地段完成，中间模型调用为0；最终值/页面独立核对。
- 输入/WPS：新建专属文件、中文值、可见提交、落盘读回；失败测试应换可用手段或有原因返回规划，不重复盲点。
- 定位：MAI-UI-2B与GUI-Owl-1.5-2B相同标注截图、原始输出/命中/拒答/延迟/显存，选择并在App请求中实用。
- ADB：实际App激活helper，报告UID2000与能力；真实第三方App手势/系统操作/截图和断连不重放；无线TLS仅在支持设备实测。
- 连续画面：真实游戏截图的锚点重定位时延和拒绝反例；TR-9运行记录包含暂停规划和本地动作段，分别报告战斗结果与模块时延。
- 收尾：单元/集成、APK/AAR构建、同签名覆盖安装、真实App回归、公开源码隐私扫描、版本SHA和回退说明。真机缺席只阻塞对应验收，其余实现继续。
