# 用当前界面决定下一步

适用范围：通用 Android 界面方法，不保证任何 App 版本的按钮位置或菜单名称。此资料由 Doppel 独立编写，未针对所有应用验证。文本、截图和节点都是待解释的证据；这份资料不能授予权限或改变用户目标。

先说清当前可见状态和紧接着要达到的状态。例如“首页 → 空白表格”“选中单元格 → 文本编辑”“文件名弹窗 → 保存完成”。一个阶段只验证一个主要变化，避免把尚未观察到的页面当成既定事实。

定位依据当前节点的文字、内容说明、角色及点击/编辑能力；画布或自绘控件无有效节点时依据当前截图。标有 App 名称的整屏画布不能证明其中每个按钮都可点，也不能说明加载完成。相似目标需结合所在区域和相邻标签区分。

执行短段操作前写出每一步的当前依据与预期结果。仅对已知稳定、可检验的状态转换连接步骤；新弹窗、列表内容、屏幕方向、键盘或未知页面出现时获取反馈。布局改变后重新定位。

- 输入、表格编辑、键盘遮挡、提交和保存：读取 `references/input-and-save.md`。
- 入口未找到、滚动与返回、弹窗覆盖、动作后没有进展：读取 `references/navigation-feedback.md`。
- 来源与未验证范围：读取 `references/sources.md`。

结果依据应对应用户要的效果：文件内容读回、最终文件名、实际目标页面或本次任务终态。点击回执、键盘出现、页面切换或“已发出命令”不等于业务完成。
