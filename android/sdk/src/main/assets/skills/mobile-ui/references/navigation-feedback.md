# 页面导航与反馈

记录当前页面的辨识特征：标题、选中标签、主要内容和阻挡层。先处理遮住目标的已识别弹窗，区分系统权限、App 提示、输入法和业务页面；弹窗关闭后重新观察，后面的控件位置可能变化。

当入口不在当前可见区域，先确认哪个区域能滚动、它大致承载什么内容，再做小幅滚动并比较新旧内容。页面列表、横向分类、地图和整屏背景不一定共享手势。手势完成只说明执行，是否滚到目标要由可见标签或内容变化证明。

返回是状态转换。输入中、弹窗中和普通页面的返回可能分别隐藏键盘、关闭弹窗或离开页面；动作前预测最邻近的一层，动作后确认实际落点。发现目标页面之外的应用时重新识别前台包，不能沿用上一 App 的资料和路径。

若点击后没有可见进展，检查反馈是否对应刚才的动作、控件是否真的可用、是否有遮挡或等待中的转场。没有加载提示、进度变化或其他依据时，不把背景变化直接解释成加载。相同状态下重复相同点击不能增加成功证据，应重新定位或调整当前假设。

阶段推进依靠新证据。进入“终端总览”只完成进入终端，尚未完成章节或关卡选择；进入“空白工作簿”只完成新建入口，尚未完成输入和保存。更新当前阶段，避免重走已完成的入口，也避免跳过尚未完成的操作。
